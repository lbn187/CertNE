# MANIFEST: what is bundled, what is regenerated, and the command behind
# every table and figure

Companion to `README.md`. `README.md` explains the scripts; this file maps
each numbered artifact of the paper to the commands that produce it and
states whether its inputs ship with the package.

## 1. Bundled

| Path | Contents |
|---|---|
| `src/` | sequence-form EFG engine, CFR/PCFR+/DPRM+ loop with the nine added training-free variants (DCFR, DCFR+, PDCFR+, HS-PCFR+, HS-DCFR, Smooth/Stable PRM+, ExRM+, IR-PRM+), certificate metrics. Plain Python: the tree the reported runs' compiled builds were generated from, plus the `certificate_state` switch added later for the bare-solver benchmarks (§3) |
| `tests/` | unit tests of `src/` (`python3 -m pytest tests`), plus `tests/ref_src_20261001/`, the frozen source snapshot the legacy bit-identical checks compare against |
| `experiments/` | run and analysis scripts (plain Python; §4 maps them to the paper's tables). Includes the three frozen protocols: `PREREG_heldout.md` (stage 1, seven arms), `PREREG_P1-3_HELDOUT_V2_20261001.md` (stage 2, sixteen arms) and `PREREG_P1-3_FRESH_20261005.md` (stage 3, seeds 128--191) |
| `experiments/side_experiment/` | audit logs of the certificate-gated control experiment quoted in Future Work (logs only; the solver that produced them is not bundled) |
| `bench_cost.py` | per-checkpoint wall-clock behind `tab:budget` |
| `bench_cost_e2e.py` | end-to-end wall-clock of the checkpoint policies and of the two bare-solver arms (in-run and exact-gap selection) |
| `figures/` | figure scripts (protocol schematic, tightness and hard-instance panels, coalition certificate) |
| `README.md`, `MANIFEST.md`, `requirements.txt`, `requirements-dev.txt` | this documentation and the environment pins |

Main-run logs are large and are not shipped. Every run script skips a run
whose log already exists, so an interrupted run resumes. The
figure scripts of the paper read these directories through the
`TBD_M1_DIR` / `TBD_POOL_V2_DIR` / `TBD_LEDUC3_JSON` environment variables
and default to the paper-side paths.

## 3. Environment

Python 3.12.9 with NumPy 2.1.2 (`requirements.txt`) is the configuration
that produced the reported trajectories. On one machine, the same compiled
binaries were rerun under CPython 3.10.21 (NumPy 2.2.6), 3.12.3 (NumPy 1.26.4)
and 3.12.9 (NumPy 2.1.2) and produced byte-identical logs for the seven
biased-Leduc paper arms at seed 0. The reported runs
used compiled builds; `src/` ships as the plain-Python tree they were
generated from, with the `certificate_state` switch behind the bare-solver
benchmarks added later (default on, which leaves the reported trajectories
unchanged). The compiled tree was verified against the
plain-Python tree it was compiled from: the two produce byte-identical result
trees on an eleven-case comparison battery covering `run_m1_seq`,
`run_arm_pool_v2`, `run_leduc3_seq` (both strict modes), `run_leduc3_pool_v2`,
`run_external` (both games), `run_external_pool_v2`, `run_m1_heldout`,
`run_extra_arms`, and a deterministic driver of the matrix game module; each
case ran twice per tree, and the JSON outputs were compared byte-for-byte
within and across the two trees after dropping the wall-clock fields.
RM+ and PRM+ arms reproduce bit-for-bit across NumPy builds;
DPRM+ Goofspiel trajectories are sensitive to last-bit floating-point
differences, so fix the NumPy version before rerunning the Goofspiel rows.
Build provenance of the reported environment (`numpy.show_config()`): the
manylinux x86_64 wheel of NumPy 2.1.2 built with gcc 10.2.1, linked against
scipy-openblas 0.3.27 (`USE64BITINT DYNAMIC_ARCH NO_AFFINITY`, Haswell
kernels selected at run time), Linux, little-endian; all BLAS thread pools
were pinned to one thread.

## 6. Not reproducible from this package

- The OpenSpiel cross-validation of the appendix is reported from a separate
  environment with `pyspiel` 1.6.3 installed; those scripts and their logs
  are not part of this package.
- The NPCFR+ and reference rows of `tab:main` are copied from the reference
  paper, not rerun here.
- `tab:verification-cost` and `tab:guarantees` are analytic tables.
- The aligned-grid wall-clock row of `tab:budget` (the 24.4 core-hour line)
  reads `results/m1_tight_strict`, a legacy run directory that no script here
  regenerates and that is not bundled. `analyze_pool16_paper.py` prints that
  row as not reproduced when the directory is absent, and `analyze_m1_seq.py`
  skips its regression block against `results/m1_tight(_strict)` for the same
  reason (pass `--no-regression`, or supply the two directories, to silence
  the message). The aligned certificate itself is logged inside
  `results/m1_tight_seq`.
- The meta-trained baseline is not reproduced (see the paper's discussion of
  the comparison protocol).
- The certificate-gated control experiment quoted in Future Work ships as
  audit logs only (`experiments/side_experiment/`); the solver that produced
  them is not part of this package and the experiment cannot be regenerated
  from it.
- The aligned three-player rerun that reproduced the original trajectory to
  floating-point precision is obtained by running `run_leduc3_seq.py`
  without `--no-strict` into a fresh `--out-dir` and comparing the two
  `nash_gap` histories; the original comparison log is not shipped.
- The nine added arms were selected from a 35-configuration pilot grid
  (seeds 0--9) by a one-per-family rule frozen before their full grid was
  launched; the pilot can be rerun with `--stage pilot`, but the tables read
  only the frozen `FULL_ARMS` list and do not depend on it.
